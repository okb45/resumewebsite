Teensy-Zybo-Game Boy Advanced

This project explores the design of a hybrid Game Boy Advance (GBA) emulator using both a Teensy 4.1 microcontroller and a Zybo FPGA board for hardware-accelerated graphics output to an ILI9486 16-bit parallel LCD. The approach separates emulation into two major components: CPU emulation and graphics rendering.

To simplify development and debugging, the emulator was first built and tested on a regular computer. This stage focused on correctness and allowed for step-by-step validation of ARM7TDMI instruction decoding, CPU pipeline behavior, and memory-mapped I/O without being constrained by embedded hardware. The emulator was structured so that the CPU emulation core could be compiled for both desktop and embedded targets.

The next stage of the project will involve porting the CPU emulation core to the Teensy microcontroller, where it will execute the game logic and memory operations. In parallel, the Zybo FPGA will be developed as a graphics accelerator, responsible for rendering tile and sprite data and driving the ILI9486 display over a 16-bit parallel interface. This division of labor is expected to balance the sequential strengths of the microcontroller with the parallel processing power of the FPGA, providing a pathway toward real-time GBA emulation on embedded hardware.

ARM7TDMI CPU Emulation

A major focus of the project was the design of the CPU emulation core, which was first implemented on a desktop computer to simplify testing and debugging. The goal was to create an emulator that could later be recompiled for the Teensy 4.1 microcontroller with minimal modification. To achieve this, the CPU core was written in a portable, hardware-agnostic style, with clean interfaces separating the processor logic from platform-specific peripherals.

The emulation process followed the fetch–decode–execute pipeline, mirroring the behavior of the ARM7TDMI processor used in the Game Boy Advance. This involved fetching instructions from emulated memory, decoding opcodes according to the ARM instruction manual, and executing the corresponding operations. Both ARM (32-bit) and Thumb (16-bit) instruction sets were supported, requiring careful implementation of condition codes, and mode switching between the two instruction sets.

This staged approach made it possible to validate the CPU core extensively on desktop hardware before porting it to the microcontroller. By separating the core logic from hardware-specific code, the emulator could run in a desktop debugger while remaining compatible with the eventual embedded target.
